# Пошук ланцюжків дублікатів у CSV на PHP

[![CI](https://github.com/MelnixDev/csv-duplicate-finder-php/actions/workflows/ci.yml/badge.svg)](https://github.com/MelnixDev/csv-duplicate-finder-php/actions/workflows/ci.yml)

[English version](README.md)

Інструмент знаходить зв’язані групи дублікатів у CSV-файлі за допомогою
перевіреної реалізації Union-Find (Disjoint Set Union).

Два записи належать до однієї групи, якщо мають однакове непорожнє значення в
одній і тій самій колонці. Зв’язки транзитивні: якщо запис A збігається з B, а
B збігається з C, усі три записи отримують однаковий `PARENT_ID`.

## Правила пошуку

- За замовчуванням порівнюються колонки `EMAIL`, `CARD` і `PHONE`.
- Значення порівнюються лише в межах однакової колонки.
- Пробіли на початку та в кінці значення ігноруються.
- Порожні значення та рядок `NULL` у будь-якому регістрі ігноруються.
- Решта значень порівнюються точно й з урахуванням регістру.
- Представником групи стає перший запис цієї групи у вхідному файлі.
- Представник посилається сам на себе.
- Порядок записів та оригінальні ID зберігаються.
- ID мають бути непорожніми й унікальними.

Наприклад:

```text
1 збігається з 2 за CARD
2 збігається з 5 за PHONE
```

Зв’язана група має вигляд `{1, 2, 5}`, і кожен її запис отримує
`PARENT_ID=1`.

## Вимоги

- PHP 8.3 або новіший
- Composer

## Встановлення

```bash
git clone https://github.com/MelnixDev/csv-duplicate-finder-php.git
cd csv-duplicate-finder-php
composer install
```

## Запуск у терміналі

Вивести результат у термінал:

```bash
php bin/find-duplicates.php examples/input.csv
```

Записати результат у файл:

```bash
php bin/find-duplicates.php examples/input.csv output.csv
```

Показати довідку:

```bash
php bin/find-duplicates.php --help
```

`index.php` залишено як сумісну точку входу:

```bash
php index.php examples/input.csv
```

## Формат вхідного файлу

CSV повинен мати заголовок із колонками `ID`, `EMAIL`, `CARD` і `PHONE`.
Додаткові колонки дозволені та ігноруються. Порядок колонок не має значення.

```csv
ID,PARENT_ID,EMAIL,CARD,PHONE,TMP
1,NULL,email1,card1,phone1,
2,NULL,email2,card1,phone2,
3,NULL,email3,card3,phone3,
4,NULL,email1,card2,phone4,
5,NULL,email5,card5,phone2,
```

Парсер підтримує стандартні CSV-значення в лапках, зокрема коми всередині
таких значень, і приймає UTF-8 BOM перед першим заголовком.

## Формат результату

Результат містить оригінальний `ID` та `PARENT_ID` представника групи:

```csv
ID,PARENT_ID
1,1
2,1
3,3
4,1
5,1
```

Повний приклад знаходиться у файлах
[examples/input.csv](examples/input.csv) та
[examples/expected-output.csv](examples/expected-output.csv).

## Алгоритм

Спочатку кожен запис утворює окрему множину. Для кожної колонки пошуку
запам’ятовується перший запис із кожним значенням. Якщо значення повторюється,
виконується `union()`. Операція `find()` використовує стиснення шляхів, а
`union()` — ранг, щоб дерева залишалися короткими.

ID представника зберігається окремо від внутрішнього кореня дерева. Тому
union-by-rank не порушує правило, за яким представником залишається перший
запис групи.

За фіксованої кількості колонок час роботи майже лінійний:
`O(n α(n))`, де `α` — обернена функція Аккермана. Використання пам’яті —
`O(n + u)`, де `u` — кількість унікальних значень у колонках пошуку.

## Розробка

Запустити тести:

```bash
composer test
```

Запустити статичний аналіз:

```bash
composer analyse
```

Запустити всі перевірки:

```bash
composer check
```

Набір регресійних тестів перевіряє транзитивні ланцюжки, незалежні злиття
груп, несуміжні ID, порожні значення, відсутність помилкових збігів між
різними колонками, CSV-значення в лапках, неправильні заголовки та запуск із
термінала.

## Поточні обмеження

- Порівняння враховує регістр після прибирання зовнішніх пробілів.
- Підтримується лише CSV із комою як роздільником.
- Вхідний файл наразі повністю зберігається в пам’яті.
- Результат навмисно містить лише `ID` та `PARENT_ID`.
